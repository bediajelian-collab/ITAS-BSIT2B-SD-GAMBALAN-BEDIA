CAMPUS LOST & FOUND - CONNECTION FIX

IMPORTANT:
The original message "Permission denied: connect" is generally generated by the
operating system, firewall, antivirus, or Java security restrictions. Changing
Java source code alone cannot override an operating-system network block.

SAME COMPUTER (recommended first test)
1. Open the project in NetBeans.
2. Run com.mycompany.campuslostandfound.server.ServerMain first.
   It should print: "Server is running!"
3. Run com.mycompany.campuslostandfound.CampusLostAndFound.
4. Set Server IP to 127.0.0.1 and Port to 5000.
5. Click Connect.

TWO DIFFERENT COMPUTERS
1. Run ServerMain on the computer acting as the server.
2. On the server computer, open Windows Defender Firewall > Advanced settings >
   Inbound Rules > New Rule.
3. Choose Port > TCP > Specific local ports: 5000 > Allow the connection.
4. Apply the rule to the appropriate network profile (normally Private).
5. On the client computer, enter the server computer's LAN IPv4 address
   (find it on the server with: ipconfig) and port 5000.
6. Ensure both computers are on the same network and that the network is
   configured as Private where appropriate.
7. If antivirus/firewall software has Java blocked, allow the Java runtime
   executable used by NetBeans. Only allow it on trusted networks.

TEST THE SERVER PORT
On the server computer, after ServerMain starts, run in PowerShell:
  Test-NetConnection 127.0.0.1 -Port 5000

On a different client computer, run:
  Test-NetConnection SERVER_IP -Port 5000

TcpTestSucceeded should be True. If it is False, the server is not listening,
the IP/port is wrong, or a firewall/network rule is blocking the connection.

The client source has also been updated to show more useful diagnostics and
to stop waiting indefinitely when the server cannot be reached.
